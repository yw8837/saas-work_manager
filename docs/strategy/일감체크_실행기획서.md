# 일감체크 실행기획서

2026년 10월 25일 · 대표·멘토 설명용 · 서비스 설계와 11월 검증 계획

## 먼저 결정할 것

일감체크는 비슷한 조건의 외주를 반복 판매하는 제작자의 일감 관리와 고객 응대를 연결한다. 크몽은 첫 고객을 찾는 경로다. 소개·홈페이지·SNS로 직접 주문받는 프리랜서까지 같은 작업 조건을 재사용하도록 설계한다.

이번 달에는 고객 검증과 광고에 우선 투자한다 (추천). 패키지·일감 관리 MVP를 출발점으로 두고 고객 대화를 일감에 옮기고 작업 결과를 다시 설명하는 시간을 줄이는지 확인한다. 앱 출시나 새로운 생성 도구 구독을 2라운드의 선결 조건으로 두지 않는다.

**현재:** 패키지·옵션 재사용, 일감 생성, 수정 기록, 웹 MVP 구현·배포. **계획:** 주문 정보를 사용하는 고객 응대, 공식 채널 수신·답장, 수락 후 차감. **검증 대상:** 시간 절감, 크몽 외 수요, 지불 의사, 실제 채널 연동. 외부 고객·매출·절감률 실적으로 제출할 자료는 현재 확인되지 않았다.

## 1. SCQA

### A를 먼저 말하기

일감체크는 반복 외주를 맡는 제작자가 주문 조건을 한 번 저장하고 여러 일감의 관리와 고객 응대에 재사용하도록 돕는 서비스다. 패키지·일감 관리 MVP를 구현·배포했다. 다음 단계에서는 고객 요청을 일감에 연결하고 확정된 진행·결과를 같은 채널로 안내해 제작자가 다시 확인하고 설명하는 시간을 줄이는지 검증한다.

| 구조 | 멘토에게 설명할 내용 | 근거의 상태 |
|---|---|---|
| S 상황 | 외주 제작자는 제작과 함께 고객별 조건 확인, 요청 정리, 진행 안내를 맡는다. | 고객 조사에서 반복 빈도와 실제 사례를 확인할 문제 가설 |
| C 문제 | 업무관리·상담 자동화 서비스가 있어도 주문 조건과 작업 상태가 연결되지 않으면 판매자가 정보를 찾아 다시 답한다. 혼자 도구를 연결하고 상담 규칙까지 관리하는 부담이 남는지 확인해야 한다. | 경쟁 기능은 존재함. 국내 표적 고객의 미해결 부담은 검증 대상 |
| Q 질문 | 고객에게 새 관리 도구를 강요하지 않고 제작자의 반복 입력과 확인형 응대를 줄일 수 있는가? | 채널별 연결 가능성과 실제 편의성을 함께 검사 |
| A 답 | 저장한 외주 조건을 재사용하는 일감 관리 위에 요청 연결과 확정 정보 안내 두 흐름을 붙인다. 제작자는 수락·추가 비용·납기 변경 같은 판단을 맡는다. | 기존 관리 MVP + 미구현 고도화 계획 |

AI로 제작 속도가 빨라져 동시 수주량이 늘었다는 설명은 시장 가설이다. AI 사용 여부·도입 시점·전후 작업시간·동시 진행 건수를 묻고 계절 수요·영업·가격 변화도 같이 기록한다. 단면 설문이나 회상만으로 인과관계를 입증했다고 쓰지 않는다. 이 가설이 약해도 실제 반복 외주 운영 문제가 확인되면 사업 검증은 계속한다.

### 60초 설명문

일감체크는 비슷한 외주를 반복해서 맡는 프리랜서를 위한 서비스입니다. 작업 기간과 수정 조건을 저장하면 다음 주문에 다시 적용할 수 있고 웹 MVP까지 구현해 배포했습니다.

이제 확인하려는 문제는 고객 응대입니다. 고객이 진행 상황이나 요청 내용을 물을 때마다 제작자가 주문을 찾고 이전 대화를 확인한 뒤 같은 내용을 다시 설명합니다. 기존 상담·업무관리 도구도 자동화를 제공하므로 저희는 패키지 설정을 재사용해 시작하기 쉽고 실제 응대 시간이 덜 드는지를 비교하겠습니다.

고객 조사는 크몽뿐 아니라 소개·홈페이지·SNS로 직접 주문받는 제작자까지 포함합니다. 공식 연동이 가능한 채널에서는 요청을 일감에 연결하고 확정된 진행·결과를 같은 대화로 안내하는 흐름을 시험할 계획입니다. 인터뷰 12명과 파일럿 6명을 목표로, 순수하게 줄어든 시간과 유료 이용 의사를 확인하겠습니다.

## 2. 크몽 밖에서 커지는 방법

고객을 플랫폼 이름보다 업무 특성으로 고른다. 기준은 반복되는 작업 범위, 재사용할 조건, 여러 고객과의 소통이다. 모든 프리랜서나 모든 기업을 시장으로 계산하지 않는다.

| 순서 | 고객군과 수주 경로 | 재사용할 것 | 확장 전 확인 |
|---|---|---|---|
| 첫 검증 | 크몽 등 마켓에서 규격형 외주를 파는 1인 제작자 | 기간·납품물·수정 조건·할 일 | 마켓 내부 관리만으로 충분한지, 외부 도구에 옮기는 비용 |
| 동시 검증 | 소개·자기 홈페이지·SNS·직접 영업으로 주문받는 제작자 | 같은 서비스의 기본 조건과 고객별 예외 | 기존 소통 방식, 반복 안내 시간, 도구 전환 부담 |
| 다음 확장 | 영상·디자인·홈페이지 유지보수 등 반복 납품하는 2~5인 스튜디오 | 서비스 템플릿·고객 응대 기준 | 담당자 권한·인수인계 수요. 팀 기능은 미구현 |
| 장기 후보 | 해외의 규격형 서비스 판매자 | 등급별 범위·기간·수정 조건 | 언어·현지 채널·결제·지원 비용을 별도 검증 |

Fiverr는 공식적으로 최대 3단계 패키지와 수정·추가 옵션을 지원한다.[S1] 크몽 외에도 같은 판매 구조가 존재한다는 근거다. 일감체크 구매 수요나 해외 시장 규모의 증거는 아니다. 재능넷·재능아지트·숨고는 국내 탐색 경로로 남기되 모든 판매자가 등급형 패키지를 판다고 가정하지 않는다. 플랫폼 자체 주문·분쟁·메신저 기능과 경쟁하므로 단일 플랫폼 안에서 충분히 해결되는 고객은 억지로 모집하지 않는다.

시장 크기는 적격 제작자 수 × 도달 가능한 비율 × 실제 유료 전환율 × 월 실수령액으로 추정한다. 각 값의 조사 전에는 TAM 숫자를 만들지 않는다. 같은 제작자가 두 플랫폼에서 활동해도 한 명으로 센다.

## 4. 핵심 기능과 서비스 흐름

### 기능 1. 고객의 요청을 일감에 다시 옮기지 않기

기존에 사용하는 공식 연결 채널에서 메시지 수신 → 검증된 고객·일감 확인 → 원문·첨부와 주문 조건 표시 → 제작자가 요청 묶음과 처리 여부 판단 → 수락 기록과 조건 반영 → 같은 채널에 처리 결과 안내.

짧은 메시지 세 개를 수정 세 번으로 세지 않는다. 문의·자료 보충·작업자 오류 보완은 회차를 쓰지 않는다. 수정 진행은 영향(1회 사용·할 일 추가)을 보여준 뒤 수락한다. 추가 범위는 가격·기간을 사람이 정하고 고객과 합의하기 전 원래 조건을 바꾸지 않는다.

### 기능 2. 작업한 내용을 고객에게 다시 설명하지 않기

제작자가 고객에게 공개할 진행 상태·납품물을 확정 → 저장된 주문 조건과 공개 정보로 안내 준비 → 허용된 응대 정책에 따라 승인 또는 발송 → 전달 결과와 재문의 기록 → 판단이 필요한 대화만 제작자에게 이관.

내부 할 일 완료와 고객 납품 완료는 다르다. 작업자는 공개 상태를 최소 한 번 갱신해야 한다. 이 시간도 비용에 포함한다. AI가 화면 밖의 실제 제작 진행을 알아낸다고 설명하지 않는다.

| 문의 종류 | 처리 설계 | 사람의 역할 |
|---|---|---|
| 확정된 진행·잔여 조건 질문 | 고객·주문을 식별하고 최신 서버 정보가 맞는지 확인한 뒤 사실 안내 후보로 처리 | 초기에는 초안 검수. 자동 전환은 별도 승인·정확도 검증 후 |
| 요청 내용 누락·복수 주문 | 추정하지 않고 확인 요청 또는 사람 이관 | 올바른 주문·요청 묶음 확인 |
| 추가 금액·납기 변경·환불·분쟁 | 자동 확답 금지 | 조건 판단과 합의 |
| 낡은 정보·연결 오류·미지원 첨부 | 확인 필요와 미전달 상태 표시 | 원문 확인·연결 복구 |

기존 MVP의 고객 링크는 접수 시 자동 기록·차감한다. 위 수락 후 차감은 새 정책 제안이다. 기존 주문에는 새 정책을 묵시적으로 적용하지 않는다.

## 5. 연결 제약을 숨기지 않는 UX

| 소통 경로 | 공식 확인 상태 | 화면에서의 약속 |
|---|---|---|
| 크몽 메시지 | 제3자 수신·답장 공개 API와 권한 경로를 조사에서 찾지 못함. 자체 FAQ 자동응답은 존재 [S5] | 자동 연결 표시 금지. 수동 기록은 기존 보조 경로이며 무입력 효과에서 제외 |
| 개인 카카오톡 | 일반 채팅 수발신 API 미제공이라는 공식 답변 [S6] | 읽기·답장 자동화 약속 금지 |
| 판매자의 기존 카카오톡 채널 | 챗봇 스킬·상담톡 수신/발신 공식 경로 존재 [S7][S8] | 판매자 권한·고객 식별·계약·비용·실제 왕복 검증 후 연결 가능. 현재 미구현 |

사업 조사 대상과 기술 파일럿은 다르다. 채널이 없는 제작자도 인터뷰한다. 자동화 시험은 이미 해당 채널을 쓰고 필요한 권한을 가진 적격군에서 한다. 개인톡 고객을 채널로 이동시킨 결과를 기존 대화 그대로의 성과로 계산하지 않는다.

처음에는 패키지 선택 → 실제 고객과 주문 연결 → 응대 허용 범위 확인이 필요하다. 닉네임만으로 고객을 연결하지 않는다. 여러 주문이 있는 고객에게는 검증된 본인 주문 중 필요한 것만 확인한다. 신원이 확인되기 전 다른 주문 제목·금액·파일을 보여주지 않는다. 과거 대화 전체를 자동으로 가져올 수 있다고 가정하지 않는다.

알림 발송과 대화 수신은 별개다. 나중에 먼저 안내를 보내는 기능에는 채널·인증·친구 상태·과금 조건이 붙을 수 있다. 카카오 Event API의 15원/VAT 별도는 해당 발송 요금일 뿐 AI·상담톡·서버 전체 원가가 아니다.[S9]

### 화면의 읽는 순서

모바일은 일감 목록 → 문의 검토 → 주문 근거 순으로 보여준다. 데스크톱은 세 영역을 나란히 볼 수 있다. 고객명보다 일감 제목·기한·다음 행동을 함께 표시해 같은 고객의 여러 주문을 구분한다. 자동 처리 내역과 판단 대기를 분리하고 홈을 빈 AI 채팅창으로 바꾸지 않는다.

버튼은 `수정 진행 · 1회 사용`, `답변만 · 0회`, `조건 협의`, `사람이 응대`처럼 결과를 설명한다. 반복 확인창은 줄이고 금액·기간·회차 변경에만 영향 확인을 둔다. 저장과 전달은 분리해 `수락 저장됨 / 고객 전달 실패`를 동시에 보여준다. 발송 실패 재시도가 다시 회차를 차감하면 안 된다.

시안은 기존 흰색·흑연색과 주의 상태의 체리색을 쓴다. 본문 16px, 주요 터치 영역 44px 이상, 색 외 상태 문구, 키보드 초점을 적용한다. 파랑·초록·베이지 배경, 장식 카드, 효과 없는 큰 숫자와 가짜 성과 배지는 쓰지 않는다.

현재 Android 오프라인 스냅샷은 계정 일치 검사를 거친 읽기용 자료다. 활성 일감 최대 30개와 일감별 미완료 할 일 최대 5개를 담는다. 전체 DB 백업이나 모든 로컬 데이터 암호화의 증거가 아니다. 원본 코드와 운영 이력은 HANDOFF 및 저장소를 기준으로 구분했다.

새 구현의 검사 기준은 계정/고객 격리, 같은 이벤트 재전송 시 1회 처리, 수락·차감·통지 예약을 묶은 원자 처리, 사람 이관 뒤 자동 응대 중지, 오래된 데이터 확답 차단이다. 고객 메시지나 첨부 안의 지시는 AI의 권한을 바꿀 수 없다. 로그에는 비밀키·원문 전체를 기본 출력하지 않고 보관 기간과 삭제 경로를 정한다.

Supabase Free 유휴 정지 위험, 실제 복원 훈련, 정책 확정 등 기존 운영 조건은 남아 있다. 이번 기획·시안 검증이 외부 베타 운영 승인이나 가동률 보장이 되지는 않는다. 모집 광고는 준비 전에는 연구 참여 모집으로 연결하고 실제 서비스 체험 안내는 해당 운영 조건을 통과한 뒤 전환한다.

## 7. 고객 조사와 모집 설계

### 모집 목표와 적격 기준

탐색 설문 유효 응답 40명, 인터뷰 12명, 파일럿 6명을 목표로 한다. 모두 계획 수치다. 설문은 시장 비율을 추정하는 대표 표본이 아니라 문제 유형을 찾는 탐색 표본이다.

주 대상은 최근 30일에 유료 외주를 수행한 1인 제작자다. 작업 범위·기간·수정 조건 중 반복되는 것이 있는 제작자를 모집한다. 동시 진행 3건 이상을 중심군으로 두고 0~2건 고객도 비교군으로 남긴다. 월 완료 건수와 최대 동시 진행 건수는 별도로 묻는다. 2~5인 팀은 확장 탐색군이며 초기 1인 표본과 합쳐 보고하지 않는다.

인터뷰 12명 중 6명은 마켓 중심, 6명은 직접·소개·홈페이지·SNS 수주 중심을 목표로 한다. 겸업자는 주 수주 경로로 한 번만 분류한다. 카카오톡 채널 보유를 전체 조사 필수 조건으로 넣지 않는다. 무료 혜택을 좋아한 응답과 실제 사용·결제 의사를 구분한다.

### 3~4분 스크리너 초안

1. 주로 어떤 외주를 하나요? 홈페이지·유지보수 / 디자인 / 영상·편집 / 글·콘텐츠 / 개발 / 기타 직접 입력.

3. 최근 30일 유료 외주를 몇 건 완료했나요? 0 / 1~2 / 3~5 / 6~10 / 11건 이상 / 잘 모르겠음.
4. 같은 기간 동시에 진행한 일감은 가장 많을 때 몇 건이었나요? 0 / 1 / 2 / 3~5 / 6건 이상 / 잘 모르겠음.

9. 그 일을 마지막으로 처리한 상황과 대략 걸린 시간을 적어주세요. 기억나지 않으면 건너뛰어도 됩니다.

### 가격과 효과를 확인하는 순서

기존 방식 → 같은 일의 시안/후보 방식 → 실패·검수까지 포함한 소요시간 → 어떤 조건에서 계속 쓸지 → 월 14,900원 사용 의사와 이유 순으로 묻는다. 응답을 실제 결제로 기록하지 않는다. 실제 유료 유지 검증은 결제·운영 조건이 갖춰진 후 별도 진행한다.

연락 가능한 후보 수는 유효 응답률에 따라 달라진다. 유효 응답 40명을 목표로 할 때 5%면 800명, 10%면 400명, 20%면 200명이 필요하다. 이 비율은 민감도 계산용 가정으로만 쓰며 실제 회신율 예측에는 쓰지 않는다. 무차별 메일을 보내는 계획도 아니다. 업체가 적격 응답 완료 인원을 계약하는지, 단순 노출·리스트만 제공하는지 구분한다.

순절감시간 = 기존 응대시간 − 새 방식의 응대·검수·정정·설정·상태 갱신 시간. 첫 2주에는 초기 설정시간을 전액 포함하고 이후 반복 운영 시간은 따로 보고한다. 설정비를 임의의 긴 기간에 나누지 않는다. 사람별 절대 절감 분량과 절감률을 같이 기록하며 기준시간이 0이면 절감률을 계산하지 않는다. 30분·30%·4명 기준은 사전에 정한 탐색 가설이며 통계적 유효성이나 유료 수요를 보장하지 않는다. 2주 결과를 월 효과로 환산하면 추정치로 표시하고 후속 관찰로 확인한다. `발송 성공`을 `고객 문제 해결`로 세지 않는다. 전체 문의 수와 자동 처리 적격 문의 수의 분모를 모두 보인다.

## 9. 실제 광고 운영을 맡기는 방법

광고 목표는 적격 연구 참여 신청이다. 서비스 자동 응대가 완성되기 전에는 `크몽·개인톡 자동 처리`, `모든 잡무 해결`, `시간 50% 절감`을 광고하지 않는다. SNS 계정 대행 로그인은 하지 않는다. 광고 계정의 제한 권한 위임도 별도 승인이 필요하다.

| 업무 | 업체에 맡길 납품 범위 | 우리가 할 일 |
|---|---|---|
| 타깃 모집 | 적격 기준 검수, 중복 제외, 연락 동의, 완료 응답 수와 모집 출처 보고 | 질문·표적 기준 확정, 인터뷰 참석·해석 |
| 한 달 광고 | 소재 2안×이미지 2종 목표, 캠페인 설정, 승인된 매체비, 주 1회 보고, 중지·수정 운영 | 사실 검토·승인, 신청자 응대, 제품 운영 조건 관리 |
| 랜딩·IR | 기존 원본 검토와 편집본, 수정 범위·횟수·납기 명시 | 실제 제품 상태·사업 가설·근거 제공, 최종 주장 책임 |

위 수량·주기는 우리가 요청할 계약 기준이지 조사된 모든 상품의 제공량이 아니다. 업체별 실제 공개 조건은 별도 비교표를 적용한다.

광고 문구 A: `외주 여러 건, 고객 요청은 어디에 정리하세요?` 설명: `반복 외주를 맡는 제작자의 작업 관리 방식을 조사합니다. 3~4분 설문과 선택 인터뷰에 참여해 주세요.`

광고 문구 B: `작업 조건은 비슷한데, 주문마다 다시 입력하고 있나요?` 설명: `패키지 조건을 다음 일감에 재사용하는 일감체크. 웹 MVP의 사용 흐름을 살펴보고 의견을 들려주실 제작자를 찾습니다.` B의 실제 체험 연결은 운영 조건 통과 후에만 켠다.

광고→연구 안내 랜딩→중립 스크리너→적격 동의자→인터뷰→별도 파일럿 초대 순서로 측정한다. UTM에는 이름·이메일을 넣지 않는다. 내부 테스트·중복·스팸은 제외하고 방문/신청/적격/면담 완료를 따로 센다. 적격신청당비용은 광고 집행비를 적격 신청 수로 나눈다. 적격 신청 0명이면 0원이 아니라 산출 불가다. 업체 수수료까지 포함한 총 모집원가도 별도 보고한다.

11월 1~7일은 문제 조사·소재 검수와 소액 탐색, 8~14일은 적격 신청과 인터뷰, 15~21일은 준비된 범위의 시안/파일럿 비교, 22~30일은 결과 정리와 IR 반영을 목표로 한다. 날짜는 제안 일정이며 신청 승인·운영 준비·참여자 확보에 따라 바뀐다. 적격 유입이 없거나 약속한 서비스 준비가 안 되면 광고를 멈춘다.

## 10. BM과 예산의 설명 기준

기존 표시 요금은 Basic 월 14,900원·Pro 월 24,900원이다. 결제는 미구현이며 시장에서 검증된 가격이 아니다. Basic을 30일로 나누면 하루 약 497원이다. 하루 가격은 보조 설명으로 쓰고 월 결제액을 먼저 표시한다.

예를 들어 작업자 시간가치를 시간당 20,000원으로 가정하면 월 14,900원은 약 44.7분이다. 한 달에 그 이상 절약하면 금액상 손익이 맞는다는 계산이지 고객의 실제 시간가치·절감 효과 증거가 아니다. 고객이 안심하고 맡길 수 있는지도 함께 확인한다.

고객당 이익은 실제 수령액에서 결제·세금 처리, AI 사용료, 메시지 발송료, 서버 배분, 고객 지원 시간을 뺀 값으로 계산한다. 새로운 CS 기능을 기존 플랜에 무제한 포함한다고 확정하지 않는다. 크몽 밖에서도 같은 문제와 지불 의사가 확인되는지 조사한 뒤 과금 단위를 결정한다.

AI 지원금 100만원은 등록 솔루션 예산이다. 현금 광고비나 모집 사례비로 자유 전환할 수 있다고 가정하지 않는다. 별도 창업활동자금 200만원과 합쳐 계산하지 않는다. 공개 금액 합계가 100만원 이하여도 필요한 대행이 포함되지 않으면 요구를 충족한 구매 조합이 아니다.

[공개 조건 재검증](../research/2026-10-25-업체공개조건-재검증.md)과 [업체 선택표](./업체선택표.md)에서 제품 가격·VAT·매체비·계정 권한·등록 여부·미확정 항목을 비교한다. 문의·신청·결제·광고는 실행하지 않았다.

## 11. 출시 전이 아니라, 검증 전에 필요한 것

- 조사: 개인정보·연락 동의·보관 기간과 모집 경로·중복 기준을 정하고 원본 응답과 반대 사례를 보존.
- 채널 시험: 공식 계약·권한·가격, 실제 고객-주문 바인딩, 정상/재전송/오류 왕복, 해제 시 자동 발송 중지.
- 서비스 체험: 정책 확정, 실제 탈퇴·복구 증거 등 기존 운영 조건. Android 실기기와 iOS 서명 환경은 별도 과제.
- 광고: 현재 구현 범위와 문구를 맞추고 매체비·수수료·계정 권한을 구분. 운영 담당자·중지 기준·보고 항목을 정함.

멘토에게 요청할 도움은 타깃 선정, 적격 모집 경로, 순절감 비교 방법, 등록 상품으로 살 수 있는 실제 대행 범위다. 세금·증빙 지원은 장기 확장 후보로 유지하고 이번 핵심 기능과 예산에 포함하지 않는다.
