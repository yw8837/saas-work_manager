질문과 소개 글에는 기간·날짜 말을 넣지 않는다. 언제 열어도 그대로 읽히게 한다.

## 고친 점 (2026-11-12, 응답 0개일 때 다시 구성)

- 14문항(필수 10개)을 7문항(필수 3개)으로 줄였다. 구획 나눔을 없애 한 화면에서 끝난다.
- 가장 알고 싶은 질문(더 쓸 수 없게 되면 얼마나 아쉬운지)을 1번에 뒀다. 필수 3개는 모두 한 번 누르면 되는 고르기다.
- 새 문항: 더 쓸 수 없게 되면 얼마나 아쉬운지(1번), 쓰기 전에 수정 횟수를 어떻게 셌는지(3번), 인터뷰용 이메일(7번, 선택).
- 가격 질문을 '월 24,900원이 어떻게 느껴지나요'에서 '한 달에 얼마까지 낼 수 있나요'(구간 고르기, 선택)로 바꿨다.
- 뺀 문항: 편했는지 5점 척도, 써 본 기능 고르기, 일의 범위가 비슷한지, 얼마나 자주 여는지, 몇 명이 함께 하는지, 동시 진행 건수, 안내·답장이 줄었는지, 도움 정도, 24,900원 느낌, 계속 쓰고 싶은지 평점. 고르기 부담이 크거나 인터뷰로 묻는 편이 정확한 것들이다.
- 링크를 보내지 않은 이유는 따로 문항을 두지 않고 6번 주관식의 설명에 넣었다.
- 응답 링크와 편집 링크는 그대로다(같은 설문을 고쳤다).

## 줄인 근거 (2026-11-12 조사)

- 문항이 늘수록 완료율이 떨어지고 15문항까지가 가장 가파르다(SurveyMonkey 분석). 앱 안 설문은 1문항이 응답률이 가장 높고 2~4문항이 비슷하며 그보다 길면 떨어진다(Refiner 2025, 설문 1,382개).
- 주관식이 많으면 중간 이탈이 늘어난다. 주관식과 인적 사항은 뒤에 둔다(Qualtrics, 옥스퍼드대 안내).
- 답을 강제하지 않고 빠져나갈 선택지를 둔다('이미 쓰지 않고 있어요', '아직 모르겠어요', 기타 직접 적기).
- '더 쓸 수 없게 되면 얼마나 아쉬운가'는 제품 적합도를 보는 표준 질문이다(Sean Ellis 검사, '매우 아쉽다' 40%가 기준선으로 알려져 있다).
- 직접 묻는 지불 의사는 실제보다 높게 나오고 표본이 작으면 방향만 볼 수 있다. 그래서 가격은 선택 문항 하나만 둔다.
- 수치는 대부분 설문 도구 회사의 자료라 방향만 참고했다.

## 문항

소개 글: 질문은 7개이고, 꼭 답해야 하는 것은 고르기 3개뿐이에요. 답변은 제품과 요금을 정하는 데 씁니다. 고객 이름이나 연락처처럼 고객을 알아볼 수 있는 정보는 적지 말아 주세요.

질문과 소개 글에는 걸리는 시간을 적지 않는다. 문항 수를 바꾸면 소개 글과 앱 팝업의 안내(`BETA_SURVEY_SIZE_TEXT`)도 같이 고친다.

1. 일감체크를 더 쓸 수 없게 된다면 어떠실 것 같나요? — 하나 고르기, 필수: 매우 아쉬울 것 같아요 / 조금 아쉬울 것 같아요 / 아쉽지 않을 것 같아요 / 이미 쓰지 않고 있어요
2. 고객에게 수정 요청 링크를 보내 보셨나요? — 하나 고르기, 필수: 보냈고, 고객이 링크로 요청을 남겼어요 / 보냈지만 고객이 링크를 쓰지 않았어요 / 아직 보내지 않았어요
3. 일감체크를 쓰기 전에는 수정 횟수를 어떻게 세셨나요? — 하나 고르기, 필수: 따로 세지 않았어요 / 기억에 의존했어요 / 메모장이나 엑셀에 적었어요 / 카톡 대화를 다시 찾아봤어요 / 기타(직접 적기)
4. 주로 어떤 분야의 외주 일을 하시나요? (여러 개 선택 가능) — 여러 개 고르기, 선택: 디자인 / 영상·사진 / 웹·앱 제작 / 글쓰기·번역 / 마케팅·운영 / 기타(직접 적기)
5. 계속 쓴다면 한 달에 얼마까지 낼 수 있나요? — 하나 고르기, 선택: 무료로만 쓸게요 / 4,900원 이하 / 9,900원 / 14,900원 / 24,900원 이상 / 아직 모르겠어요
   - 설명: 유료 결제는 아직 없어요. 요금을 정하기 전에 의견을 듣는 질문이에요.
6. 아쉬웠던 점이나 바라는 기능을 편하게 적어 주세요. — 긴 답, 선택
   - 설명: 링크를 보내지 않으셨거나 고객이 쓰지 않았다면 그 이유도 적어 주시면 큰 도움이 돼요.
7. 이야기를 더 들려주실 수 있다면 연락받을 이메일을 적어 주세요. — 짧은 답, 선택, 이메일 형식 검사
   - 설명: 적지 않으셔도 됩니다. 적어 주신 이메일은 사용 경험을 여쭙는 연락에만 쓰고 다른 곳에 쓰지 않습니다. 지워 달라고 하시면 바로 지웁니다(yeolmae@studioyeolmae.com).

## 응답 흐름

- 구획 나눔과 건너뛰기가 없다. 한 화면에서 답하고 제출한다.

## 이메일 문항에 대하여

- 7번은 적고 싶은 사람만 적는 선택 문항이다. 이메일 주소 자동 수집은 꺼 두었다.
- 받은 이메일은 사용 경험을 묻는 연락에만 쓴다. 지워 달라는 요청이 오면 설문 응답에서 지운다.
- 개인정보처리방침에는 설문 이메일에 대한 항목이 없다. 문항 설명에 쓰임과 삭제 방법을 직접 적었다.

## 앱의 '의견 보내기'와의 관계

- 앱의 의견 보내기 화면은 제보 유형·화면·사용 기간 같은 값을 설문에 미리 채워 넘기게 만들어져 있지만, 이 설문에는 그 문항이 없고 운영에는 문항 번호(`NEXT_PUBLIC_FEEDBACK_ENTRY_*`)가 연결돼 있지 않다. 지금은 의견 화면에서 눌러도 빈 설문이 열린다. 따로 정리할 일로 남긴다.

## 홈페이지 연결

Sites 배포 환경의 `NEXT_PUBLIC_FEEDBACK_FORM_URL`에 응답 링크를 연결한다. 14일 Pro 이용권(2026-11-03 30일에서 변경)을 쓰는 계정에는 사용 7일째부터 작업 화면 상단에 설문 안내("써 보니 어떠셨나요?")가 나타난다. 안내는 이용권이 끝난 뒤에도 계속 보이며, 설정의 의견 보내기 화면에서도 같은 폼을 열 수 있다.

이용권이 끝난 뒤 설문 팝업(2026-11-12 추가):

- 조건: 베타 Pro 이용권이 끝났고(`betaExpired`) 설문 주소(`NEXT_PUBLIC_FEEDBACK_FORM_URL`)가 있을 때, 작업 화면(오늘·일감·패키지·설정 등 앱 틀 안의 화면)에 들어오면 뜬다. 이용권을 쓰는 중이거나 유료·다른 권한으로 `betaExpired`가 거짓이면 뜨지 않는다. 고객 화면(/r/…)과 공개 페이지에는 뜨지 않는다. 판정은 화면이 준비된 뒤(하이드레이션 뒤)에 한다.
- 버튼 세 가지: '설문 작성하기'는 설문을 새 탭으로 열고 닫는다(다시 안 뜸). '나중에 할게요'는 닫고 3일 뒤 접속 때 다시 띄우며, 3번 고르면 더는 띄우지 않는다. '다시 보지 않기'는 닫고 다시 띄우지 않는다. 닫기(X)·Esc·바깥 누르기는 '나중에 할게요'와 같다.
- 기록 위치: 이 브라우저의 localStorage `ilgamcheck:beta-survey-prompt:v1:<계정 id>`(로컬 모드는 `:local`). 서버·DB에는 남기지 않아 다른 기기·브라우저에서는 다시 뜰 수 있다. 저장소를 못 쓰는 브라우저에서는 그 방문에 한 번만 띄운다. 판정 함수는 `src/lib/beta-survey-prompt.ts`.
- 띠와의 관계: 팝업이 떠 있는 동안에는 상단 띠를 숨기고, '나중에 할게요'로 닫으면 띠가 다시 보인다. '설문 작성하기'나 '다시 보지 않기'를 고른 계정에는 이 브라우저에서 띠도 숨긴다.
