# 작업 화면 리디자인

## 확정한 방향

사용자가 파랑·초록·베이지와 전형적인 AI 생성 SaaS 화면을 배제하고, 참고 자료 조사와 디자인 선택을 위임했다. 이번 범위는 웹과 Capacitor 앱이 함께 사용하는 작업 화면이다. 운영 데이터·인증·푸시 설정과 마케팅 랜딩은 별도다.

흰색·흑연색의 스튜디오 작업 목록으로 구성한다. 여러 고객의 일감을 훑고, 하나의 일감으로 좁혀 완료·수정·납품을 처리하는 순서가 우선이다. 짙은 체리색은 지연·오류 등 주의가 필요한 상태에만 사용한다. 완료와 고객 대기는 색 대신 아이콘·문구로 구분한다.

## 참고 자료와 적용 판단

- [Linear UI redesign](https://linear.app/now/how-we-redesigned-the-linear-ui): 공식 글과 실제 After 화면을 확인했다. 내비게이션·본문의 명확한 분리와 시각적 잡음 축소를 적용한다. 어두운 개발자 콘솔의 외형은 복제하지 않는다.
- [Todoist features](https://www.todoist.com/features): 오늘 할 일과 필터 중심의 정보 구조를 참고한다. 브랜드 색과 홍보용 화면 구성은 가져오지 않는다.
- [Things features](https://culturedcode.com/things/features/): 작업을 그룹으로 나누고 필요한 세부 정보를 단계적으로 보여주는 방식을 참고한다.

검토한 구조는 납품 목록, 고객별 폴더, 스튜디오 제작 목록, 편집 타임라인, 정산 원장, 요청 인박스, 현장 노트다. 이 서비스의 핵심은 거래액·차트보다 오늘 처리할 항목이므로 스튜디오 제작 목록을 선택했다. concept-seed 기록은 `51596c9b`, 할당 순번 3이다. 출력 후 Windows 런타임 종료 오류가 있었으므로 도구 전체 성공으로 기록하지 않는다.

카탈로그 대안 중 콘솔형 구조는 정보 구분 면에서 경쟁력이 있지만 휴대폰의 읽기 밀도와 맞지 않는다. 노란 안내판은 주의의 우선순위만, 격자 도록은 정렬 규칙만, 인쇄 슬리브와 카세트 레이블은 일관된 체계만 참고한다. 특정 외형을 섞지는 않는다. 사용자 위임 및 기존 code-first 설정에 따라 별도 이미지 시안 대신 실제 UI로 구현한다.

## 화면 계약

- 첫 화면: 제목·날짜 → 일감 범위 선택 → 압축된 요약 → 우선 처리 목록.
- 동일 고객의 여러 주문은 고객명과 일감명을 함께 표시한다.
- 일감 선택 시 할 일·대기·다가오는 마감·알림을 같은 범위로 좁힌다.
- 삭제·완료된 일감이 선택되어 있으면 전체 진행 일감으로 돌아간다.
- 모바일은 가로 표 대신 목록을 쓰며 남은 수정 횟수를 숨기지 않는다.
- 5개 하단 탭과 기존 생성·완료·수정 흐름은 유지한다.
- 선택 상태는 중립 명도, 위험 상태는 아이콘·문구와 제한된 체리색으로 표시한다.
- 새 사용자에게 테스트 고객·가짜 일감을 넣지 않는다. QA의 12개 일감은 격리된 테스트 자료다.

## 구현 경계

`src/styles/workspace.css`를 `.appFrame` 아래로 한정한다. 기존 랜딩·공개 수정 폼의 스타일과 사용자 데이터는 유지한다. 새 라이브러리와 이미지 자산은 추가하지 않는다. 전체 제품의 색상 정책 변경으로 확대하지 않는다.

디자인 브랜치는 `codex/mobile-workspace-design`, 기반은 모바일 PR #13의 `6c75674`다. 검증 결과와 최종 화면 기록은 별도 검증 문서에 남긴다. 기존 Android APK에 이 디자인이 포함되었다고 표현하지 않는다.
