2026-10-24 기준. 웹/API 연결 확인과 외부 베타 공개 승인은 다른 단계다.

## 1. 개인정보 안내 — 운영자 확인 및 게시 전 검토

`docs/MOBILE-BETA-OPERATIONS.md`에 구현 기준 데이터 표가 있다. 다음 문구는 **게시 후보**이며 운영 정책이나 법률 검토가 확정됐다는 의미가 아니다.

> 일감체크는 Google 계정으로 로그인합니다. 계정과 일감의 기준 데이터는 Supabase에 저장하며, 현재 프로젝트의 DB 리전은 서울입니다. 웹에서는 저장 전 초안과 복구용 상태를 브라우저에 보관할 수 있습니다. 모바일 앱은 로그인 정보와 서버 저장이 확인된 진행 중 일감 최대 30건을 기기의 보안 저장소에 보관하고, 오프라인에서는 조회만 지원합니다.
>
> 휴대폰 알림을 켜면 기기 등록 정보와 알림 토큰을 처리합니다. 새 고객 수정 요청을 알리기 위해 Google Firebase Cloud Messaging을 사용합니다. 푸시 본문에는 고객명과 수정 요청 내용 대신 일반 안내 문구를 사용합니다. Firebase Analytics는 사용하지 않습니다.
>
> 앱의 알림 등록을 해제하거나 로그아웃하면 서버 기기 등록 삭제를 요청합니다. 네트워크 오류가 있으면 완료 여부를 다시 확인해야 합니다. OS 알림 권한 해제와 서버 기기 등록 삭제는 별개입니다. 계정 삭제 시 연관 기기 등록과 작업공간 데이터도 삭제하는 구조이며, 실제 탈퇴 검증을 거친 뒤 공개합니다.

### 공개 전 반드시 확정할 내용

| 확인 | 현재 사실 / 필요한 조치 |
| --- | --- |
| 처리자·국외 처리 | Supabase·OpenAI Sites·Google FCM의 계약 주체, 처리 국가/시설, 이전 시점·방법·항목·보유기간·권리 행사 방법을 현 계약과 맞춘다. ‘무료 베타이므로 유료 출시 때 처리’로 미루지 않는다. 법적 충분성은 운영자 검토 필요 |
| FCM ID 삭제 | Google 안내의 Firebase 설치 ID 삭제와 일감체크 DB의 토큰 삭제를 혼동하지 않는다. 현재 두 동작의 전 과정 삭제 실증은 없다 |
| 보유기간 | 무효 토큰 비활성화와 계정/기기/요청 삭제 연동은 구현됨. 독립적인 30일 자동 정리는 없음. 구현하지 않은 보유기간을 약속하지 않는다 |
| 로그·백업 | 공급자 설정과 실제 백업 정책을 읽어 기간을 확정. 임의로 ‘즉시 완전 삭제’라고 표시하지 않는다 |
| 게시 절차 | 검토된 문구→새 정책 버전/digest→DB 정책 계약→웹/API 배포→동의 화면 재확인. 승인 전 finalized=false 유지 |

Google 공식 안내는 FCM을 글로벌 처리 서비스로 분류하며, 설치 ID 삭제 API 호출 뒤 운영·백업 시스템에서 제거되는 데 최대 180일이 걸릴 수 있다고 설명한다. 이것을 우리 DB 토큰의 보유기간이라고 쓰지 않는다. [Firebase 개인정보·보안](https://firebase.google.com/support/privacy)

## 2. 실제 탈퇴·복구 증거

| 항목 | 안전한 실행 조건 | 완료 증거 |
| --- | --- | --- |
| Google A/B 격리 | 데이터 없는 전용 Google 테스트 계정 2개. 세션은 채팅/Git 없이 로컬 보안 환경에만 전달 | 동일 계정으로 혼동하지 않으며 A 데이터에 B 접근 차단, 수정 요청·중복 처리 확인 |
| 실제 계정 탈퇴 | 삭제할 전용 계정과 그 테스트 데이터만 정확히 지정하고 영구 삭제 승인 | Google 재인증, 오래된/잘못된 인증 거부, Auth 사용자·연관 데이터 삭제 확인 |
| 논리 백업 | 저장소 밖 암호화 저장소를 확인하고 고객 데이터 export 대상 승인. pg_dump 또는 실행 중 Docker 필요 | export manifest·hash. public dump만으로 Auth·Storage까지 복구된다고 주장하지 않음 |
| 복구 연습 | 운영과 다른 Supabase ref·별도 비공개 검증 배포·필요한 Auth 복구 방법 준비 | 과거 데이터 건수/ID 대조 + 복구 후 로그인 + A/B 격리 + smoke. 운영 DB에 복원하지 않음 |

이번 PC 확인: Docker CLI는 있으나 Linux 엔진에 연결되지 않았고 `pg_dump`·`psql` 명령이 PATH에 없다. 전용 recovery 배포·프로젝트 및 지정된 암호화 export 폴더도 준비된 기록이 없다. 비용이 생길 수 있는 새 프로젝트나 유료 전환을 임의로 만들지 않는다.

복구 검증은 `npm run supabase:restore:verify:dry` → 실제 별도 복원 → `npm run supabase:restore:verify` 순서다. dry 통과는 복구 성공이 아니다. 명령 도움말과 `.env.hosted.example`의 새 Google 세션 항목을 사용한다. 이 검사는 전용 A 작업공간을 덮어쓰므로 실제 운영자 계정을 사용하지 않는다.

Supabase Free 프로젝트에서 유휴 정지 위험이 제거됐다고 보장하지 않는다. 유료 백업/PITR도 현재 활성화했다는 증거가 없다. [Supabase 백업 안내](https://supabase.com/docs/guides/platform/backups)

## 3. 휴대폰 연결

Android USB 연결 (추천): 무선 페어링보다 단순하고 연결 상태를 확인하기 쉽다.

1. 휴대폰 설정 → 휴대전화 정보 → 소프트웨어 정보 → 빌드번호를 7회 누른다. 기종마다 메뉴가 조금 다르며 PIN은 사용자가 직접 입력한다.
2. 개발자 옵션 → USB 디버깅을 켠다.
3. **데이터 전송이 되는 USB 케이블**로 현재 PC에 연결하고 잠금을 푼다.
4. 휴대폰의 ‘USB 디버깅을 허용할까요?’에서 이 PC인지 확인 후 허용한다. 출처를 모르는 PC에는 허용하지 않는다.
5. 연결됐다고 알려주면 이후 설치·실기기 테스트를 재개한다. 필요하면 Windows 제조사 ADB 드라이버를 확인한다.
6. 검증을 마치면 USB 디버깅을 끄거나 디버깅 승인 목록을 취소한다. OEM 잠금 해제·루팅은 필요 없다.

설치 파일: `D:/SaaS/01_일감체크/release-artifacts/2026-10-23-mobile-beta/일감체크-내부검증.apk`.
현재 APK는 Android 내부 검증용이며 Play Store 출시본이 아니다. 폰에는 Android Studio를 설치할 필요 없다.

iPhone은 Android APK로 설치할 수 없다. 현재 Apple Developer·Mac/Xcode·APNs가 없어 네이티브 배포 준비 완료로 표시하지 않는다. 비용·가입은 별도 결정한다.

[Android 공식 기기 연결 안내](https://developer.android.com/studio/run/device)
