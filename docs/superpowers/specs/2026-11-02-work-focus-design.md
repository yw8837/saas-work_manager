# 작업에만 집중 — 일감체크 완성도 설계 (2026-11-02)

상태: 사용자가 "응 전부 진행하고 서비스 사용 설명서도 글보단 이미지위주로"(2026-11-02 오전)라고 해서 질문 없이 끝까지 진행한다. 이 문서는 기록·빌더 검토·사용자 확인용이다. 병합·운영 배포는 사용자 승인 뒤에만 한다.

## 0. 사용자 지시 (요지 그대로)

- "서비스 완성도 최고로 만들어줘. 핵심기능 > 돈내고 써야할 기능에 집중해주고, 인터뷰에 나온사항도 고려(세금이나 최소단가, 클라이언트 소통이랑 인터뷰문제 등). 우리가 만들건 외주작업에 있어서 작업에만 집중할수있는 서비스를 제공하는거야. 흩어진 외주작업 통합도 하고."
- "UXUI도 신경쓰고, 어렵고 복잡하면 안 쓰겠지?? 중요한건 2번이랑 5번" → 2 = 돈 내고 쓸 핵심 기능, 5 = 외주 작업에만 집중하게 하는 서비스(사용자 확인).
- "전부 진행하고, 서비스 사용 설명서도 글보단 이미지 위주로."
- 사용자가 "빠진 것 없다"고 확인한 이해:
  1. 작업에만 집중 = 주문마다 따라오는 잡무를 일감체크가 맡는다.
  2. 무기 3개(주문 30초 등록 / 시작 안내 한 방 / 수정 범위 정리)를 먼저 세게 한다.
  3. 통합 = 직접 등록 + 받은 곳(수주처) 표시·거르기. 자동 연동은 안 한다.
  4. 소통 = 상황별 카톡 문구.
  5. 최소 단가 = 손해 기준 아래면 경고. 표준 단가는 안 준다.
  6. 세금 = 월별 매출·원가 정리와 내보내기. 세무 판단은 안 한다.
  7. 인터뷰 문제를 기능에 맞대어 본다.
  8. 완성도 = 실제 흐름을 돌아보며 불편을 고친다.

## 1. 왜

외주 제작자는 크몽·숨고·소개·직접 문의로 주문을 받고, 주문마다 자료 요청·질문·진행 안내·수정 처리·납품 안내를 카톡으로 직접 쓴다. 일감체크는 이 반복 잡무를 맡아 제작자에게 제작과 범위·가격·납기 결정만 남긴다(`PRODUCT.md` 제품 정의).

돈을 낼 이유는 기능 개수가 아니라 **"다음 주문에서 덜 쓰고 덜 찾는다"** 이다. 그래서 새로 넣는 것은 모두 아래 셋 중 하나를 해야 한다.
- 제작자가 카톡에 직접 쓰던 말을 대신 준비한다.
- 여기저기 흩어진 주문 정보를 한곳에서 바로 보게 한다.
- 화면에서 입력·누르기·읽기를 줄인다.

어렵거나 복잡하면 안 쓴다(사용자). 그래서 기준은 **"입력 칸 하나 덜, 누르기 한 번 덜, 글 한 줄 덜"** 이다. 처음 쓰는 사람이 설명서 없이 3분 안에 첫 주문을 만들어 고객에게 안내를 보낼 수 있어야 한다(`PRODUCT.md` 디자인 원칙).

## 2. 목표 · 안 할 것 · 실패로 볼 것

**목표**
1. 처음 쓰는 사람의 첫 카톡 문구에 받을 자료와 착수 전 질문이 기본으로 들어간다(무기 2가 처음부터 보임).
2. 일감 화면 어디서든, 지금 상황에 맞는 고객 안내 문구를 한 번에 복사한다.
3. 고객이 남긴 새 요청이 일감 화면 첫 화면에서 보인다.
4. 주문마다 받은 곳(크몽·숨고 등)이 붙고, 목록에서 받은 곳별로 모아 본다.
5. 내가 정한 최소 기준보다 덜 남는 패키지·주문이면 한 줄로 알린다.
6. 달마다 완료한 주문의 매출·원가·남는 돈을 받은 곳별로 보고, 표 파일로 내려받는다.
7. 화면의 어려운 말과 영어(Todo 등)를 없앤다.
8. 사용설명서는 그림이 주인공이고 글은 한 줄씩이다. 그림 안에 누를 곳이 표시돼 있다.

**안 할 것(범위 밖, `PRODUCT.md`·10절 동결 유지)**
- 크몽·숨고·카톡 대화의 자동 연동·수집·자동 답장
- 세금 계산·신고 대행·세무 조언, 표준 단가·시세 제공
- 새 요청 웹 알림, 고객 결과 승인, 포함 범위 확인(D8), 링크에서 질문 답하기, 대화 붙여넣기 기록
- 결제, 팀 기능, 네이티브 앱 확장
- DB migration(이번 변경은 작업공간 JSON 문서의 선택 칸만 더한다)

**실패로 볼 것(기술적으로 돌아가도 실패)**
- 새 일감 등록에 필수 칸이 늘거나, 첫 링크까지 누르기가 지금(6번)보다 늘어난다.
- 경고가 잔소리처럼 화면마다 뜨거나, 기준을 정하지 않은 사람에게도 뜬다.
- 월별 정리가 세금 계산·신고 금액처럼 읽힌다.
- 고객에게 가는 문구·링크에 금액·원가·받은 곳·작업자 연락처가 나간다.
- 설명서 글이 지금보다 길어진다.

## 4. 바꿀 것

### 단계 A — 무기 3개가 처음부터 보이고 쉽게 (F1~F8, F10)

**A1. 업종 예시 패키지에 받을 자료·질문 기본값** (F1)
- 4개 업종 예시 패키지 전부에 `briefQuestions` = 엔진의 기본 질문 3개(`DEFAULT_BRIEF_QUESTIONS`)를 넣는다.
- `intakeItems`는 업종별 2~3개(예시이며 사용자가 고친다). 내 판단으로 아래처럼 둔다.
  - 웹·홈페이지: 로고 파일(있으면) / 가게·회사 소개 글 / 넣을 사진
  - 디자인: 가게·브랜드 이름(한글·영문) / 원하는 색이나 분위기
  - 영상: 원본 영상 파일 / 넣을 자막·문구 / 원하는 배경음악(있으면)
  - 촬영: 촬영 장소 주소 / 촬영 날짜·시간 후보 / 꼭 찍을 장면
  - 참고 사이트 주소·참고 이미지는 받을 자료에 두지 않는다. 기본 질문 2번이 이미 참고 예시를 묻는다(시장조사 R2, 계획 작업 8.8).
- 이미 저장된 사용자 패키지는 바꾸지 않는다(새 사용자와 업종을 다시 고르는 빈 작업공간에만 적용).

**A2. 저장 직후 안내의 주 버튼을 '카톡 문구 복사'로** (F2)
- 큰 버튼 = 카톡 문구 복사(문구 안에 링크·자료·질문이 다 있음). 두 번째 = 링크만 복사. 세 번째 = 고객 화면 미리보기.
- 문구 미리보기는 접지 않고 버튼 아래에 말풍선처럼 보여 준다(무엇을 보내는지 보고 누르게). 휴대폰 첫 화면 안에 주 버튼이 있어야 한다(기존 E2E 기준 유지).

**A3. 일감 화면에 '고객에게 보낼 말'을 늘 둔다** (F3, F12 — 단계 B2에서 상황을 늘림)
- 안내 띠를 닫아도 같은 문구를 다시 복사할 수 있다. 위치는 일감 화면 위쪽(핵심 정보 줄 바로 아래, 할 일 목록보다 위).
- 착수 전 질문 구획의 '남은 것 다시 보내기 문구 복사'는 이 구획의 한 상황으로 옮긴다(복사 버튼이 두 군데 생기지 않게). 질문 체크·메모는 그 자리에 그대로 둔다.

**A4. 새 요청을 위로** (F4)
- 확인 대기 요청이 있으면 일감 화면 맨 위(제목 아래)에 한 줄 띠: "고객 요청 N건이 확인을 기다려요 · 보기"(누르면 수정 요청 구획으로 이동).
- 오늘 화면 '우선 처리'에는 지금 마감이 된 할 일만 있고 확인 대기 요청은 맨 위 알림 한 줄에만 나온다(빌더 체크로 확인). 그래서 '우선 처리'에 요청 줄을 넣는다. 이 줄은 할 일처럼 체크 버튼이 아니라, 누르면 그 일감의 수정 요청 구획으로 가는 줄이다.

**A5. 쉬운 말** (F5) — 화면에 보이는 글만 바꾼다(코드 이름은 그대로).

| 지금 | 바꿀 말 |
|---|---|
| Todo, Todo 5개, Todo 추가 | 할 일, 할 일 5개, 할 일 추가 |
| 자동 생성 Todo / 상대 기한 | 자동으로 만들 할 일 / 시작 며칠 뒤 |
| 합성돼요 | 채워져요 |
| Hosted: … | (앞말 없이) 저장이 끝나면 링크에 반영돼요. 재발급하면 이전 주소는 못 써요. |
| 알림 큐, 타임라인 | 알림 목록, 기록 |
| 예상 마진 / 마진율 | 남는 돈(예상) / 남는 비율 |

빌더는 `grep`으로 화면 글을 모두 찾아 같은 원칙으로 고친다. 법률 문서(약관·개인정보처리방침)는 손대지 않는다.

**A6. 이름 반복 줄이기** (F6)
- 저장된 제목은 바꾸지 않는다. 고객 이름이 바로 옆에 보이는 곳(일감 제목 아래, 목록, 오늘, 카톡 문구)에서는 제목 앞의 "고객이름 · "을 떼고 보여 준다. 사용자가 제목을 직접 바꾼 경우는 그대로 둔다.

**A7. 긴 설명 줄이기** (F7)
- 일감 화면 옆 구획의 설명 문단은 한 줄로 줄이고, 수정 횟수 규칙 설명은 "수정 횟수는 이렇게 세요" 접기 하나로 모은다. 로컬 모드 안내처럼 상황에 꼭 필요한 문장은 남긴다.

**A8. 띄어쓰기** (F8) — 스냅샷 구획의 패키지 이름과 "추가 옵션 없음" 사이를 띄운다.

**A9. 설명서로 가는 길** (F10) — 프로필 메뉴에 '사용설명서'(→ `/guide`)를 넣는다.

### 단계 B — 흩어진 주문을 한곳에 + 고객 소통 (F9, F12)

**B1. 받은 곳(수주처)**
- 값: 크몽 / 숨고 / 소개 / 직접 문의 / 기타(내 판단: 5개 고정, 기타에 글은 안 받음).
- 일감마다 선택 칸 하나. 없어도 된다(예전 일감은 표시 안 함).
- 새 일감: 1번 '고객 이름' 카드 안에 작은 칩 한 줄 "어디서 받은 주문이에요?(선택)". 필수 4칸 약속은 그대로다. **가장 최근에 만든 일감의 받은 곳을 기본으로 골라 둔다**(대부분 같은 곳에서 받으니 누르기 0번). 설정 칸에 따로 저장하지 않는다: 두 기기에서 거의 동시에 다른 곳으로 일감을 만들면 설정 칸이 충돌해 자동 병합이 멈추기 때문이다(빌더 체크, `workspace-provider.tsx` 병합 충돌 처리).
- 일감 화면: 제목 위 작은 표시. 두 번 안에 바꿀 수 있어야 한다. 받은 곳은 고객 링크·수정 횟수와 상관없으니 **완료한 일감에서도 바꿀 수 있다**(지난달 정리를 고칠 수 있게).
- 일감 목록: 줄마다 받은 곳 표시. 받은 곳이 두 군데 이상이면 목록 위에 "크몽 2 · 숨고 1 · 소개 1" 칩이 생기고, 누르면 그곳만 거른다. 검색어에도 받은 곳 이름이 걸린다.
- 오늘 화면: 일감 줄에 작은 표시.
- 고객 링크·카톡 문구·고객 화면 미리보기에는 절대 안 나간다.

**B2. 상황별 카톡 문구** ('고객에게 보낼 말' 구획, A3)
- 상황 칩을 누르면 문구가 말풍선으로 보이고 '복사' 한 번이면 끝. 복사가 막히면 글을 선택해 둔다(기존 방식).
- 지금 일감 상태에 맞는 칩만 보이고, 가장 알맞은 칩이 먼저 골라져 있다. 순서(위가 우선):
  1. 수정 반영 알림 — 방금 '수정 완료'를 눌렀을 때(같은 날 완료한 수정이 있을 때)
  2. 남은 것 요청 — 아직 못 받은 자료나 답 못 받은 질문이 있을 때(기존 문구)
  3. 답 기다림 — '고객 대기'인 할 일이 있을 때
  4. 시안 확인 부탁 — 진행 중일 때 늘
  5. 시작 안내 — 늘(저장 직후 안내와 같은 문구)
  6. 범위 밖 안내 — 범위 밖으로 분류한 요청이나 초안 추가요청이 있을 때
  7. 납품 안내 — 할 일을 다 끝냈거나 일감을 완료했을 때
- 문구 원칙(기존 `client-share.ts` 원칙을 따름): 고객 이름 인사로 시작, 금액·원가·작업자 연락처·받은 곳은 넣지 않음, 링크는 링크가 켜져 있고 저장이 끝났을 때만 넣음, 남은 수정 횟수는 실제 값으로. 다 쓴 주문에 "1회로 세요"라고 쓰지 않는다.
- 문구 초안(빌더가 다듬되 뜻은 유지):
  - 수정 반영: "요청하신 수정을 반영했어요. 포함 수정 {n}회 중 {used}회를 썼고, 남은 수정은 {remaining}회예요. 확인해 보시고 더 고칠 부분은 링크에 한 번에 남겨 주세요." (남은 수정 0회면 마지막 문장 대신 "다음 요청부터는 추가 작업으로 따로 말씀드릴게요.")
  - 답 기다림: "혹시 앞서 여쭤본 내용 보셨을까요? 답을 주시면 바로 이어서 진행할게요. 급한 건 아니니 편하실 때 알려 주세요."
  - 시안 확인 부탁: "작업한 것을 보내 드려요. 확인해 보시고 고칠 부분은 링크에 한 번에 남겨 주세요. 남은 포함 수정은 {remaining}회예요." + 링크
  - 범위 밖 안내: "말씀하신 내용은 처음 정한 작업 범위 밖이라 추가 작업으로 따로 진행돼요. 진행을 원하시면 비용과 일정을 정리해 알려 드릴게요."
  - 납품 안내: "작업을 모두 마쳤어요. 최종 결과물은 이 대화로 보내 드릴게요. 맡겨 주셔서 감사합니다. 더 필요한 게 생기면 이 대화로 편하게 말씀해 주세요."

### 단계 C — 최소 기준과 월별 매출 (가볍게, F13·F14)

**C1. 최소 남길 돈(한 건)**
- 설정 칸 하나: "한 건에 최소 남길 돈"(원, 비우면 경고 안 함). 위치는 **패키지 화면 맨 위**(값을 정하는 곳 옆, 내 판단).
- 남는 돈 = 금액 − 예상 원가(지금 계산 그대로).
- 기준을 정한 경우에만, 기준보다 적으면 화면마다 한 줄로 알린다("남는 돈 {x}원 · 내 기준보다 {y}원 적어요"): 패키지 화면(고르고 있는 패키지는 편집 칸, 나머지는 목록), 새 일감(휴대폰 아래 띠 또는 데스크톱 미리보기 중 보이는 한 곳). 이미 만든 일감 화면에는 띄우지 않는다(시장조사 R7, 잔소리 방지 — 작업 8.8에서 바꿈). 색은 주의색(체리)만, 막지는 않는다(저장 가능).
- 시세·표준 단가·"얼마를 받으세요" 같은 말은 쓰지 않는다.

**C2. 월별 정리**
- 일감 목록 위에 '월별 정리' 버튼 → `/jobs/summary`(작업 화면 안, 새 메뉴는 안 만듦).
- 한 달 단위(◀ 2026년 11월 ▶): 완료한 주문의 금액 합계·예상 원가 합계·남는 돈·건수, 받은 곳별 합계, 그달 완료 주문 목록. 진행 중 주문 합계는 따로 한 줄.
- 기준 달 = 완료한 달. 일감에 `completedAt`(완료 시각)을 새로 기록한다(완료를 되돌리면 지움). 이 칸이 없는 예전 완료 일감은 마지막 수정 시각으로 넣고 "완료 시각 기록 전 주문"이라고 표시한다.
- 금액 = 주문 조건 + 확정한 추가요청(지금 `amount` 그대로).
- 표 파일 내려받기: CSV(엑셀에서 한글이 깨지지 않게 BOM, 줄바꿈 CRLF). 열 = 완료일, 고객, 일감, 받은 곳, 패키지, 주문 금액, 예상 원가, 남는 돈(예상), 시작일, 마감일. 그달 / 올해 전체 두 가지. 링크 토큰·수정 요청 내용은 넣지 않는다.
- 안내 한 줄: "세금 신고 때 참고하려고 모은 정리예요. 세금 계산이나 신고는 하지 않아요."

### 단계 D — 이미지 위주 사용설명서 (F11, 사용자 지시)

- 그림이 주인공: 휴대폰 화면 그림을 크게, 그림 안에 **누를 곳 테두리 + 번호 동그라미**를 찍는다(캡처할 때 그림 위에 그려 넣음). 그림은 필요한 부분만 잘라 작게 보이지 않게 한다.
- 글: 장마다 제목 한 줄(행동), 설명 한 줄(30자 안팎). 더 긴 설명은 "자세히" 접기에만.
- 순서는 무기 3개를 따른다.
  1. 주문 30초 등록: ① 패키지 한 번 저장(받을 자료·질문 포함) ② 주문 오면 네 가지 고르기(받은 곳 칩 포함)
  2. 시작 안내 한 방: ③ 카톡 문구 하나 복사(말풍선 미리보기) ④ 답·자료 오면 체크
  3. 수정 범위 정리: ⑤ 요청은 링크로, 확인 대기 → 수정 완료 때 1회 ⑥ 범위 밖은 추가요청
  4. 더 편하게: ⑦ 상황별 보낼 말 ⑧ 월별 정리·표 파일
  - 가입 그림은 맨 위 작은 그림 하나로 줄인다.
- 장마다 '직접 해 보기' 버튼은 하나씩만. 맨 위 그림 띠(목차)는 유지한다.
- '아직 안 되는 것'은 그대로 두고 지금 상태로 고친다.
- 그림은 `e2e/capture/guide-screens.capture.ts`(로컬 모드 예시 데이터)로 다시 찍는다. 첫 실행 체크리스트가 쓰는 그림도 새 그림으로 바꾼다.
- 설명서 글자 수는 지금(1,094자)보다 적어야 한다.

## 5. 데이터 · 저장 · 보안

- 새 칸은 모두 선택 칸이다: `Job.source`, `Job.completedAt`, `AppSettings.minMarginPerJob`. (받은 곳 기본값은 설정 칸 없이 최근 일감에서 계산한다 — B1.)
- 작업공간은 JSON 문서로 저장되고, 저장 코드는 일감과 설정의 모르는 칸을 지우지 않는다(`storage.ts`의 `settings: candidate.settings ?? …`, 일감은 통째로 저장). 그래서 DB migration이 필요 없다는 것이 내 판단이다. 빌더는 hosted 저장 경로와 서버 함수가 칸을 거르지 않는지 기존 PGlite 시험으로 확인한다.
- 고객 공개 경로(고객 링크 서버 함수·보기, 카톡 문구)는 받은 곳·금액·원가·남는 돈을 쓰지 않는다. 바꾸지 않는다.
- JSON 백업 내보내기는 새 칸을 그대로 담는다(링크 토큰 제외는 기존대로).
- CSV는 브라우저 안에서 만들고 사용자 기기로만 내려간다. 서버로 보내지 않는다.
