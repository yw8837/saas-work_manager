# 일감체크 가입·베타 권한·배포 보안 설계

## 목적

공개 가입 사용자가 이메일 인증과 로그인 뒤 길을 잃지 않고 베타 코드를 적용하거나 무료 플랜으로 시작하도록 한다. 베타 Pro는 계정당 총 1회, 30일만 서버에서 허용한다. Sites 배포 상태는 단순 환경값 존재가 아니라 연결된 Supabase의 현재 런타임 계약까지 확인한다.

## 사용자 흐름

1. 공개 랜딩에서 `무료로 시작하기`를 누른다.
2. 이메일·비밀번호와 필수 정책 동의로 가입한다.
3. 이메일 확인이 필요한 프로젝트라면 확인 뒤 로그인한다.
4. 첫 로그인 후 베타 코드 안내 화면을 한 번 보여준다.
5. 코드를 적용하면 즉시 30일 Pro가 열리고 작업공간으로 들어간다.
6. 코드가 없으면 `무료로 시작`을 눌러 작업공간으로 들어간다.
7. 건너뛴 사용자는 설정에서 나중에 코드를 입력할 수 있다.

## 권한 규칙

- Hosted 환경의 권한 근거는 Supabase `subscriptions`와 `invite_redemptions`다.
- 서로 다른 캠페인 코드를 포함해 계정당 베타 혜택은 총 1회만 적용한다.
- 코드 적용 성공 시 기존과 같이 30일 Pro를 부여한다.
- 코드 사용 이력은 이후 Basic 월 14,900원에서 월 9,900원으로 12개월 제공할 대상 판별 근거로 보존한다.
- 이미 사용한 계정에는 코드를 바꿔도 기간을 연장하지 않고 같은 안내를 준다.
- 로컬 개발 모드는 기존 데모 코드 동작을 유지하되 계정 단위 제약과 동일하게 한 번만 허용한다.

## UI와 상태

- `BetaActivationGate`가 정책 동의를 마친 Hosted 사용자에게만 첫 진입 안내를 보여준다.
- `AppSettings.betaCodeOnboardingCompletedAt`로 건너뛰기 또는 성공 완료를 계정 작업공간에 저장한다.
- 이미 서버 베타 권한이 있으면 안내를 다시 띄우지 않는다.
- 설정 화면은 적용 코드 원문이나 내부 표식 `server`를 표시하지 않고 `베타 Pro 적용됨`과 만료일만 보여준다.
- 적용 중에는 버튼을 비활성화하고 중복 요청을 보내지 않는다.

## 배포 상태와 실패 처리

- Sites `/api/health`는 Supabase URL·service-role 값의 존재만 보지 않는다.
- 제한 시간과 응답 크기를 둔 데이터 없는 RPC로 현재 서비스 역할 키가 기대한 프로젝트·마이그레이션 계약에 연결되는지 확인한다.
- 확인 실패 시 503과 `ready: false`를 반환하며 키·상류 응답·오류 본문은 노출하지 않는다.
- 성공 응답은 기존 런타임 readback 도구가 검증할 수 있는 정확한 스키마를 반환한다.

## 보안 검증 범위

- 소유한 일감체크 프로젝트의 로컬 코드와 공개 베타 배포만 검사한다.
- 의존성 취약점, 비밀키 정적 노출, 보안 헤더, 인증 없는 권한 RPC, 코드 재사용·브루트포스 제한, 계정 간 데이터 격리(RLS/IDOR), 공개 수정 링크 입력을 확인한다.
- 실제 가입·격리 검증은 전용 테스트 계정만 사용하고 생성한 테스트 데이터는 검증 후 정리한다.
- 알려지지 않은 모든 제로데이가 없다고 보증하지 않는다. 검사 시점에 재현·확인 가능한 취약점을 수정하고 남은 외부 의존 위험을 보고한다.

## 완료 기준

- 새 안내 화면과 계정당 1회 규칙의 회귀 테스트가 실패 후 통과한다.
- 전체 단위 테스트, 타입 검사, 린트, Sites 빌드가 통과한다.
- Supabase 마이그레이션을 연결 프로젝트에 적용하고 현재 계약을 읽어 확인한다.
- 공개 Sites 배포 후 health, 주요 경로, 인증 화면, 모바일 폭을 다시 확인한다.
- 승인된 테스트 계정이 준비되면 두 계정 격리 검증까지 통과한다.
